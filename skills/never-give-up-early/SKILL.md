# 不要过早放弃

## 反面案例（真实发生）

**目标**：让一个商用软件在虚拟机里正常启动。它启动时会检测运行环境，检测到虚拟机就拒绝运行。

**我的做法**：自己逐项改了 CPU 标识、固件信息、网卡、显卡加速、十几条虚拟机配置项和注册表。

**结果**：全部失败。我的结论是："这条路走到头了，它的检测层次足够深，不值得继续。"

**用户的反问**："你只凭一篇二手转载帖、自己试了一轮，就判了死刑。调研太少。"

**之后**：开了 4 路互相独立的调研，其中一路直接找到了一个现成的开源驱动，装上就解决了。**前后 30 分钟。**

## 问题出在哪

不是知识不够，是**过早收敛**：

| 实际行为 | 应有的行为 |
| --- | --- |
| 自己穷举 5~6 种配置 | 先搜"别人是怎么解决这个问题的" |
| 读完一篇文章就下结论 | 覆盖代码托管、官方文档、论坛，中英文都查 |
| 把"我试的都不行"当成"没有可行方案" | "我试的"只是全部方案里很小的一块 |
| 用"层次太深""太复杂"这种模糊判断收尾 | 要么给出具体的排除证据，要么继续找 |

## 信号：发现自己正要说这些话时，触发本流程

- "这条路走不通 / 走到头了"
- "技术上不可行 / 应该不支持 / 没办法绕过"
- "建议换个方案"（但其实没有确认原方案已经被排除）
- "可能是 X 导致的，建议你手动……"（把问题推回给用户）

## 强制流程

### 第一步：多路调研，至少 3 路，每路角度不同

```
角度 A：针对这个具体机制，有没有专用工具、补丁、绕过方案
角度 B：换环境、换前提，能不能根本不触发它
角度 C：绕开这个环节，从别的入口达成目标
角度 D：重审自己的分析前提，哪个假设没有验证就被当成了事实
```

- 有子智能体或并行能力时，**一次全部派出去**。每一路都只给原始事实，**不要把你的既有结论喂给它们**，并明确允许它们推翻你。
- 没有并行能力时，按这几个角度依次搜索，每个角度用不同的关键词。
- 没有联网能力时，把你会去搜的关键词和来源列给用户，请用户帮忙查，或者授权你用别的方式查。

### 第二步：检索既有方案

```
代码托管：搜 "<机制或报错原文> fix | workaround | patch | tool"
官方来源：文档 / changelog / issue tracker（含已关闭的 issue）/ 源码本身
社区：这个领域老手聚集的论坛和邮件列表，中英文各查一遍
长文：论文、会议演讲、技术博客的原始出处（不要只看转载）
```

**用报错原文搜索**，不要只用你自己概括的描述来搜。找"已经解决过这个问题的人"，比重新发明一遍快一个数量级。

### 第三步：审计假设

- 判定"失败"的标准对吗？（比如把"没弹窗"当成"程序要退出"）
- 失败信息读完整了吗？日志、报错的后半截、退出码、弹窗原文（见 dialog-handling、screenshot-first）
- 有没有一条明显的路径完全没考虑？（换方案、换平台、换入口、换版本）
- 问题会不会根本不在你以为的位置？（以为在 A 层，实际在 B 层）
- 每次改动是一次只改一个变量吗？同时改五处、全部失败，什么也排除不了。

## 什么情况才真的可以停

只有三种：

1. **可行路径已经穷举**，每条都有具体的失败原因（不是"感觉很难"）。
2. **收益和代价严重不匹配**，而且判断基于真实成本，不是猜测（比如需要专用硬件、要停机、会破坏数据）。
3. **目标本身有问题**（目标已经不存在，或者达成了也没用）。

**"我试了几次都失败"不属于其中任何一种。**

## 边界：不放弃 ≠ 不汇报，也 ≠ 越界

- **调研有成本**。长时间调研时，每一轮都简短告诉用户：试了什么、排除了什么、下一步打算做什么，让用户可以随时叫停或调整方向。
- **权限拒绝、安全限制、用户明确的约束不算技术障碍**。不要把"想办法绕过它们"当成坚持。遇到这些情况，说明情况，问用户。

## 真要说"不行"时，用这个格式

```
目标：……
已排除的路径：
  1. <路径> —— 失败证据：<具体报错 / 数据 / 文档出处>
  2. ……
查过的来源：<代码托管搜索词、issue 链接、文档章节……>
还没试的路径及其代价：……
如果要继续，需要：<权限 / 硬件 / 时间 / 用户的决定>
```

写不出"失败证据"和"查过的来源"这两栏，就说明还没到可以说"不行"的时候。

## 检查清单

- [ ] 说"走不通"之前开了几路独立调研？少于 3 路就再开
- [ ] 用报错原文在代码托管和 issue tracker 搜过吗？中英文都搜了吗？
- [ ] 有没有把未经验证的假设当成事实
- [ ] 失败原因是具体的，还是"感觉难"
- [ ] 换一个人来做，他会先试什么
- [ ] 结论是否按上面的格式附上了证据
