# 风格要配得上用途

## 问题

AI 写 UI 有一套惯性审美，不管做什么都往上套：

- 毛玻璃卡片（`backdrop-filter: blur()` + 半透明白）
- 新拟态（neumorphism）的凸起凹陷阴影
- 紫色到蓝色的渐变，渐变按钮、渐变文字、渐变边框
- 深色背景上飘着几团模糊的彩色光斑
- 霓虹发光的 `box-shadow`，悬停时放大、浮起、旋转
- 每个区块都是一张 24px 圆角的卡片，标题前面放一个 emoji
- "✨ AI 驱动"、"🚀 立即开始" 式的文案

结果：一个给财务用的报销审批工具、一个运维用的日志查看器，看起来像游戏启动器或者加密货币落地页。用户每天要用八小时，看着花，找东西慢，也显得不专业、不可信。

反过来也有：一个给朋友玩的小游戏、一个抽签转盘、一个宠物日记，被做成了灰白表格加默认蓝按钮，一点意思都没有。

**风格不是"好不好看"的问题，是"合不合适"的问题。**

## 第一步：看项目里已经有什么

优先级从高到低：

1. **项目已有的设计系统 / 组件库 / 主题文件**（`tailwind.config`、`theme.ts`、CSS 变量、Figma 链接、品牌规范）：照着用，不要另起炉灶。
2. **项目里已有的页面**：新页面要和它们是一家人。
3. **平台规范**：Windows 原生程序遵循 Fluent / WinUI，macOS 遵循 HIG，Android 遵循 Material。平台规范里的材质（比如 Windows 11 的 Mica / Acrylic）是正当的，用在平台规定的位置（窗口背景、浮出菜单），而不是给每张卡片都加一层模糊。
4. 以上都没有，才轮到你根据场景判断。

## 第二步：判断场景

看这几个信号：

| 信号 | 偏向克制 | 偏向活泼 |
| --- | --- | --- |
| 谁在用 | 员工、专业人士、客户的客户 | 普通玩家、朋友、孩子、粉丝 |
| 怎么用 | 每天长时间用，反复做同一件事 | 偶尔打开，玩一会儿 |
| 内容 | 表格、数字、表单、日志、代码 | 图片、角色、故事、成就、互动 |
| 出错的代价 | 高：钱、数据、合同、生产环境 | 低：重来一次就好 |
| 用户想要的感受 | 可靠、高效、专业、不打扰 | 有趣、惊喜、有个性、想分享 |

## 第三步：按场景选方向

### 商务 / 生产力 / 内部工具 / 数据后台 / 开发者工具

- **配色**：中性色为主（白、浅灰、深灰），**一个**强调色用在主操作和关键状态上；状态色（成功/警告/错误）有固定含义，不拿来装饰。
- **字体**：系统字体或一款成熟的无衬线字体；数字用等宽或 `font-variant-numeric: tabular-nums`，列能对齐。
- **密度**：信息密度中到高，表格行高紧凑，留白服务于分组，不是为了显得"高级"。
- **装饰**：几乎没有。小圆角（4~8px），细边框或很浅的阴影，不用渐变、发光、毛玻璃、背景光斑。
- **动效**：只用于反馈（加载、展开、状态变化），150~200ms，不做入场动画、悬停放大、视差。
- **图标**：一套风格统一的线性图标（Lucide、Fluent Icons、Material Symbols），不用 emoji。
- **文案**：直接、具体："保存"、"导出 CSV"、"3 条记录待审批"。

### 娱乐 / 游戏 / 创意 / 社交 / 儿童 / 个人兴趣

- **配色**：可以鲜艳、大胆、多彩，有记忆点；可以有主题色系、渐变、插画背景。
- **字体**：标题可以用有个性的展示字体，正文依然要好读。
- **装饰**：插画、贴纸、纹理、角色、手绘元素都可以用，**但要贴合主题**，而不是随手套一套通用"炫酷"效果。像素风游戏就做像素风，童话主题就做童话感，而不是统一的紫色霓虹。
- **动效**：可以更丰富：弹性、粒子、庆祝动画、音效，给操作以奖励感。
- **文案**：可以有语气、有个性、有梗。

### 中间地带

面向普通消费者的工具类产品（记账、待办、日历、健身记录）、作品集、产品落地页：基调克制、可用性优先，在少数地方（空状态、完成时刻、品牌色、插图）加入个性。

> 活泼不等于 AI 惯性风格。毛玻璃、紫蓝渐变、霓虹光斑放到娱乐场景里，也只是"通用 AI 风"，不是这个产品的风格。好的活泼是**有主题的**。

## 不确定时：问用户

场景不明显、或者用户的需求本身就可以有多种做法时，**先问，再写**。问法要具体，给出可以直接选的方向，而不是"你喜欢什么风格？"：

```
✓ "这个工具风格上你倾向哪种？
   A. 简洁专业：浅色背景、中性色、紧凑表格，像 Linear / Notion
   B. 友好轻松：圆润一些、柔和配色、有少量插图，像 Duolingo 的设置页
   C. 有个性：大胆配色和动效，适合展示或娱乐
   不确定的话我先按 A 做一版。"
```

如果你所在的环境能直接渲染，也可以做两三个小样（只是同一个界面的不同配色和字体）让用户选。

**不需要问的时候别问**：用户已经说了用途（"给公司财务用的"）、项目里已有风格、或者需求明显（"做个俄罗斯方块小游戏"）时，直接按判断做，在结尾说一句你选的方向，方便用户纠正。

## 第四步：做完自查

把界面上的每一处装饰拿出来问：**去掉它，用户会失去什么？** 如果答案是"什么都不会失去"，而这是一个工具类界面，就去掉。

逐条对照：

- 搜一下代码里的 `backdrop-filter`、`linear-gradient`、`box-shadow` 里的彩色发光、`animation`、emoji：每一处都是有意为之吗？
- 强调色是不是只出现在主操作和关键状态上？还是到处都是？
- 截图看一眼（见 background-friendly）：第一眼看到的是内容和主操作，还是装饰？
- 换成用户的身份想：每天打开它八小时 / 玩它十分钟，这个风格合适吗？

## 边界

- 用户明确要求某种风格（"就要赛博朋克风"、"做得炫一点"），按用户的来，哪怕是工具类。
- 用户给了参考图、参考网站、品牌规范，以参考为准。
- 演示、营销、展示类页面可以比日常工具更有表现力，但依然要贴合品牌和受众。

## 检查清单

- [ ] 项目里有没有现成的设计系统、主题、已有页面？我照着用了吗？
- [ ] 这是什么场景？谁在用、用多久、出错代价多大？
- [ ] 场景不明确时，我给出具体方向问过用户了吗？
- [ ] 工具类界面：没有毛玻璃、紫蓝渐变、霓虹发光、光斑背景、emoji 图标、无意义动效？
- [ ] 娱乐类界面：有贴合主题的个性，而不是灰白表格，也不是通用 AI 炫酷风？
- [ ] 强调色只用在该用的地方？
- [ ] 每一处装饰都说得出它的用处？
